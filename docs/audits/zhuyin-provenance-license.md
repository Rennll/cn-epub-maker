# Zhuyin assets provenance and licensing audit

## Scope and baseline

This audit records the provenance and licensing status of the two legacy Zhuyin assets currently present in the repository:

- `fonts/ToneOZ-Zhuyin-Kai-Traditional.ttf`
- `fonts/phonic_table_Z.txt`

The repository state used as the disposition baseline is commit `87877ca9d262ad2ac2fb4b7cdc6b79c4e1fa874a` (2026-09-05). The legacy HanWang Zhuyin font workaround has already been removed at that baseline.

This document is a provenance/maintenance record, not a formal legal opinion.

## 1. ToneOZ-Zhuyin-Kai-Traditional.ttf

### Role in this repository

The font is not used by the V2.1 code path. It is retained as a possible future asset for a native Zhuyin/IVS rendering implementation.

The file is a derived/distributed font rather than an original single-source font. Its upstream project is ToneOZ's Zhuyin font project. The relevant upstream description identifies the Traditional variants as based on the CNS11643 Full Character Library, with Zhuyin glyphs based on But Ko's `GenyoMinBopomofo-Regular`, and Pinyin/non-Chinese glyphs based on Klee One and LXGW WenKai.

### Upstream sources and licenses

The provenance identified during the audit is:

| Component | Upstream source | License / terms |
| --- | --- | --- |
| Traditional Chinese character repertoire/base | CNS11643 Full Character Library / 全字庫 | Government Open Data License v1.0 (also distributed by the dataset under an alternative OFL 1.1 licensing option; the applicable license should be checked against the upstream distribution actually used) |
| Zhuyin glyphs | But Ko / ButTaiwan `GenyoMinBopomofo-Regular.ttf` | Apache License 2.0 |
| Pinyin and non-Chinese glyphs | FONTWORKS Klee One and LXGW WenKai | SIL Open Font License 1.1 |
| ToneOZ Traditional font project | ToneOZ `toneoz-font-zhuyin` | The upstream project states that the resulting fonts are free for commercial and personal use; component/source notices remain relevant |

The ToneOZ project should therefore not be described simply as an "SIL OFL" font. It is a multi-source derivative font with several upstream licensing/provenance obligations.

### Modifications made in this repository

The repository history shows that the font was imported as part of the March 2026 Zhuyin/IVS work. The same work also included changes intended to improve punctuation behavior for vertical text. Earlier in that sequence, the legacy HanWang font had its punctuation glyph mappings modified/replaced; that older workaround is now removed from the repository as of the baseline commit.

For the ToneOZ TTF specifically, the repository must be treated as containing a modified derivative rather than an untouched upstream copy. The March 2026 commit describes the font as having punctuation modified for vertical display. Therefore, if the TTF remains distributed, its upstream provenance and the repository's modifications should remain documented together.

### Disposition

**Retain for now.**

Rationale:

1. V2.1 does not need to activate or package the font.
2. The font has a plausible and traceable future role in a native Zhuyin/IVS implementation.
3. Its upstream provenance is sufficiently identifiable to maintain it responsibly, provided the repository does not reduce its license description to a single inaccurate label.
4. Keeping the font does not require retaining the old `add_zhuyin_ivs.py` implementation.

Future implementation should independently verify the current upstream notices and preserve the applicable attribution/license files before shipping the font in a release.

## 2. phonic_table_Z.txt

### Role in this repository

`fonts/phonic_table_Z.txt` is a pronunciation/polyphone data table associated with the old Zhuyin IVS implementation. It is not part of the V2.1 processing pipeline.

The repository's March 2026 commit states that the table was imported from the ToneOZ project and contains thousands of polyphonic entries. Upstream investigation shows that the file is not merely a copy of one Ministry of Education table. It is a project-generated compilation from multiple source tables.

### Upstream construction and provenance

The ButTaiwan/bpmfvs build process (`phonetic/make_ptable.rb`) constructs `phonic_table_Z.txt` from several intermediate tables:

- A: `phonic_table_A.txt`, generated from `source/phonic_table_src.txt`, corresponding to the Ministry of Education's 《國語一字多音審訂表(初稿)》. The upstream source license record identifies this source as Public Domain.
- B: `phonic_table_B.txt`, generated by parsing `source/moe_chongbian.txt`, the Ministry of Education's 《重編國語辭典修訂本》. The upstream source license record identifies this source as CC BY-ND 3.0 Taiwan.
- C: `phonic_table_C.txt`, generated from `source/phonic_chemical.txt`, the National Academy for Educational Research chemical-element pronunciation data. The upstream source license record identifies this source as Public Domain.
- D: `phonic_table_D.txt`, derived from an intersection of CNS data and Chewing input-method data. The upstream source license record identifies CNS data as Government Open Data License v1.0 and the Chewing source files as LGPL-2.1.
- E: `phonic_table_E.txt`, project-maintained/manual additions, including items such as light-tone and place-name readings.
- F: `phonic_table_F.txt`, based on the 1999 version of the one-character-multiple-pronunciation review table.

The build process then combines these sources and uses Chewing data to determine reading order before writing the final `phonic_table_Z.txt`.

The upstream `phonetic/source/LICENSE.txt` explicitly records these different source licenses. It also describes these files as reference data rather than program code.

### Licensing conclusion

There is **no clean single-license conclusion for the final `phonic_table_Z.txt`** based on the provenance currently established.

In particular:

- It must not be labeled simply Public Domain because some of its inputs are not Public Domain.
- It must not be labeled simply CC BY-ND 3.0 Taiwan because the final file is a compilation containing multiple other sources and project-authored material.
- It must not be labeled MIT, Apache 2.0, or another permissive software license merely because the surrounding source code uses such a license.
- The fact that ToneOZ distributed the file does not by itself establish a clear, independent file-level license for redistribution by this repository.

The important distinction is that the provenance is traceable, but the final compiled data file does not have a single clearly documented redistribution license that is suitable to assume for a software repository without further upstream confirmation.

### Disposition

**Remove from this repository for V2.1.**

Rationale:

1. V2.1 does not use the file.
2. The old `add_zhuyin_ivs.py` path that consumed it is not part of the desired V2 architecture.
3. The file is a mixed-source derived data compilation with no single clean file-level redistribution grant established by this audit.
4. Removing an unused ambiguous-provenance data file reduces maintenance and licensing uncertainty without preventing a future Zhuyin implementation.

This is a conservative repository-maintenance decision, not a finding that the file is necessarily unlawful to redistribute.

## 3. Relationship to the old Zhuyin implementation

The old `add_zhuyin_ivs.py` implementation was a post-processing adapter: it operated on an already-generated EPUB, used pronunciation data and pypinyin/OpenCC-related tooling, inserted Bopomofo IVS representations into XHTML, and then repackaged the EPUB.

That implementation should not be preserved merely because the two assets above have historical relevance. The future architecture should instead keep pronunciation resolution, reading/annotation semantics, IVS encoding, and EPUB rendering as separable concerns.

In particular, retaining the ToneOZ font does not imply retaining the old script or the old data table.

## 4. Recommended V2.1 disposition summary

| Asset | V2.1 use | Decision |
| --- | --- | --- |
| `fonts/ToneOZ-Zhuyin-Kai-Traditional.ttf` | None | **Retain**, as a future-use asset with accurate provenance/license documentation |
| `fonts/phonic_table_Z.txt` | None | **Remove**, because it is an unused mixed-source derivative data file with unresolved single-license status |
| `add_zhuyin_ivs.py` | None | **Remove**, because it belongs to the legacy EPUB post-processing architecture |

Future Zhuyin work should not treat any of these legacy implementation details as an architectural contract. A later implementation can independently select pronunciation data, resolver logic, IVS encoding, and rendering integration.
